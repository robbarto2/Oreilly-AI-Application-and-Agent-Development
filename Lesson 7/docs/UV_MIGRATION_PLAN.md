# Plan: Migrate Lesson 7 Python tooling from `.venv` + pip to uv

**Status (repo): Done.** Lesson 7 root now has **`pyproject.toml`** and **`uv.lock`**; the README trains with **`uv sync`** / **`uv run`**. Follow the checklist below only if you are reproducing or auditing the migration.

This document originally described moving from **`pip install -r requirements.txt`**-only to uv (see [README.md](../README.md)). The web app (`npm`) is unchanged; only the **Python / RL** workflow uses **uv**.

## Goals

- Install and lock dependencies with **uv** (`pyproject.toml` + **`uv.lock`**).
- Standardize commands: **`uv sync`** (environment) and **`uv run …`** (training).
- Keep **`requires-python`** aligned with the README (**3.10+**).

## Prerequisites

1. Install [uv](https://docs.astral.sh/uv/getting-started/installation/) (`curl …` or package manager).
2. From this directory (`Lesson 7/`), optionally remove the old env after you confirm uv works:

   ```bash
   deactivate  # if a venv shell is active
   rm -rf .venv
   ```

   (Safe: `.venv/` is gitignored.)

## Steps (implement in order)

### 1. Add `pyproject.toml`

Create **`Lesson 7/pyproject.toml`** describing the project and dependencies (mirror today’s [requirements.txt](../requirements.txt)):

| Current `requirements.txt` | Move into `[project].dependencies` |
|----------------------------|-----------------------------------|
| `gymnasium>=0.29.0`        | same constraint (or pin after lock) |
| `numpy>=1.24.0`            | same |
| `stable-baselines3>=2.3.0` | same |
| `torch>=2.0.0`             | same |

Minimum metadata to include:

- **`[project].name`** — e.g. `lesson7-rl` (not published; local only).
- **`[project].version`** — e.g. `0.0.0`.
- **`[project].requires-python`** — `>=3.10`.
- **`[build-system]`** — use uv’s default/hatchling pattern as generated by `uv init`, or follow [uv’s project layout](https://docs.astral.sh/uv/concepts/projects/layout/).

**Alternative:** from `Lesson 7/`, run `uv init --no-readme` (if supported in your uv version), then:

```bash
uv add "gymnasium>=0.29.0" "numpy>=1.24.0" "stable-baselines3>=2.3.0" "torch>=2.0.0"
```

That writes `pyproject.toml` and updates the lockfile in the next step.

### 2. Lock and create the environment

From `Lesson 7/`:

```bash
uv lock
uv sync
```

- **`uv.lock`** should be **committed** to the repo (do not add it to `.gitignore`).
- **`uv sync`** creates/updates **`.venv/`** and installs exactly what the lockfile says.

If **`torch`** fails to resolve or you need a specific wheel source (CPU-only Linux, etc.), adjust using uv’s **index / extra index** docs and re-run `uv lock`. On macOS, the default PyPI resolution often works for training with MPS/CPU; fix any resolution errors when you run step 4.

### 3. Optional: pin interpreter

For stable classrooms/CI:

```bash
uv python pin 3.12   # or 3.10 / 3.11 — matches your policy
```

This may create **`.python-version`**; commit it if you want everyone on the same minor version.

### 4. Verify training

```bash
uv run python rl/train.py --out public/policy.json --timesteps 50000
```

Confirm the script runs and `public/policy.json` updates. Then run the web app (`npm run dev`) and toggle **RL agent** as today.

### 5. Update [README.md](../README.md)

Replace the “Train the policy” block with uv-first instructions, for example:

```bash
cd Lesson 7   # or your path
uv sync
uv run python rl/train.py --out public/policy.json --timesteps 400000
```

Add a one-line note: **Install uv:** link to Astral docs.

### 6. Decide what to do with `requirements.txt`

Pick one:

| Option | When to use |
|--------|----------------|
| **A. Remove** | Everyone is expected to use uv; README only documents `uv sync`. |
| **B. Keep, generated** | Run `uv export --format requirements-txt -o requirements.txt` (or equivalent in your uv version) after lock changes; helps pip-only users. |
| **C. Keep, frozen** | Leave as-is temporarily with a comment “deprecated; use uv” until the next major cleanup. |

Recommend **A** or **B** for clarity; avoid two sources of truth without automation.

### 7. Repo hygiene

- Ensure **`.venv/`** stays in [`.gitignore`](../.gitignore) (already present).
- Do **not** gitignore **`uv.lock`**.
- If CI later runs training/tests, use **`uv sync`** + **`uv run`** there too.

## Rollback
